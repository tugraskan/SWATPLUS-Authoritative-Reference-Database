# Changelog

This file summarizes significant repository-wide changes. Individual record
changes are traced through the Git history and the pull request that reviewed
them; there is no separate row-level change-log file to maintain.

This repository does not publish independent versioned releases or release
ZIPs. Accepted changes accumulate on `main` and are periodically copied into a
patched SWAT+ Editor `swatplus_datasets.sqlite` for an upstream Editor pull
request.

## 2026-08-06 — Current workflow

### Repository and review workflow

* Moved the authoritative files to `database_files/` and consolidated schemas,
  metadata, scripts, tests, and detailed documentation under `internal/`.
* Retired the independent release/tag/ZIP pipeline. The maintained hand-off is
  now `internal/scripts/patch_editor_dataset.py`, which patches a copy of the
  Editor's current dataset for deliberate submission to `swatplus-editor`.
* Removed `database_changes.csv`, `compatibility_matrix.csv`, and their
  automation because Git commits, pull requests, and reviews already provide
  the record-level audit trail. `internal/CHANGELOG.md` remains a concise record
  of repository-wide events only.

### Data and Editor hand-off

* Corrected decision-table precision so deliberately offset boundary values in
  `scen_lu.dtl` and `flo_con.dtl` retain six decimal places.
* Verified the patch-and-submit workflow against the shipped Editor dataset.
  The patcher currently reads 24 official-dataset files: 20 map one-to-one to
  Editor tables and four `.dtl` files form one decision-table group. It leaves
  the seven supplemental files and the two excluded Editor tables untouched.
* Documented two Editor-side reader defects that prevent safe replacement of
  `septic_sep` and `cal_parms_cal`; both remain explicit exclusions until fixed
  upstream.

## 2026-08-05 — Bootstrap snapshot (metadata version 2026.2.0)

Authoritative reference database sourced from the official SWAT+ Editor
reference dataset.

### Data

* All core reference files are serialized verbatim from tables in the official
  SWAT+ Editor reference dataset (`swatplus_datasets.sqlite`, v4.0.0, SWAT+
  rev. 62) using SWAT+ Editor's own `fileio` writers, so each file matches, byte
  for byte, what the editor writes into a project. Per-file source table, record
  count, and checksum are recorded in `internal/metadata/bootstrap_sources.json`.
* Seven files that the official dataset does not carry are retained as
  supplemental in `internal/metadata/external_sources.json`: the direct-read databases
  `manure_db.frt`, `manure_om.frt`, `transplant.plt`, `puddle.ops`, and the
  example/unread-by-model files `metals.mtl`, `salt.slt`, `pathogens.pth`.

### Validation & tooling

* `internal/schemas/swatplus-62.0.0.json` — the SWAT+ source-derived
  description of every input database file (fields read, Fortran types, units),
  generated by `swatplus-doc-builder`.
* `internal/scripts/schema_sync.py` — compares the committed data against that
  schema and fails on drift not recorded in
  `internal/metadata/schema_drift_waivers.json`.
* `internal/scripts/schema_diff.py` — diffs two schema artifacts so adopting a
  new SWAT+ release is reviewed as a specific list of format changes.
* `internal/scripts/validate_database_files.py` — file-level validation (field
  counts, data types, header drift, manure cross-references, canonical
  filenames).
* Full unit + integration test suite under `internal/tests/`.

### Known schema-drift (waived, tracked)

* `plants.plt` — the official dataset omits the four SWAT+ 62 carbon-module tail
  columns (`meta_frac`/`str_frac`/`lig_frac`/`pl_class`), which are read
  conditionally and default otherwise. Waived until the editor dataset emits
  them. See `internal/metadata/schema_drift_waivers.json`.
* `pesticide.pes` — `pl_uptake` carries the editor's uniform `0.01` migration
  default rather than curated per-pesticide values (review note).

### Notes

* Source-file header versions are provenance only, not tested compatibility.
* No SQLite database is committed. The later maintainer workflow generates a
  patched copy outside the repository for review upstream; it does not change
  SWAT+ or SWAT+ Editor source code.
